**Category:** 4 Logic-heavy  |  **Primary baseline (G2):** B2  |  **Status:** written before any agent output exists.

**G2 intent:** Empty-state hint shown when a list is empty unless the user dismissed it this session (A§2.9)

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The page shows a list of notes that starts empty. An "Add note" button appends one note per press; each note has a "Remove" button. While the list is empty, a hint "No notes yet. Add your first note." is shown together with a "Dismiss" button. Pressing "Dismiss" hides the hint for the rest of the session, even if the list later becomes empty again. Do not store the dismissal in persistent storage (localStorage, cookies): when the app is opened again in a new session (a new tab or window; a restart for the PVC runtime) the hint is shown again if the list is empty.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- hint = visible text matching /no notes yet/i
- controls: add = button named /^add/i; remove = buttons named /remove|delete/i; dismiss = button named /dismiss|close|got it|hide/i
- new session: baseline = a new page (tab) in the same browser context (fresh sessionStorage/in-memory state, shared localStorage); PVC = `new_session` (in-memory state discarded, persisted app storage kept)

## Checklist items

### G01.1 — Hint shown when empty and not dismissed  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load (1280 px): the list is empty (no Remove button) and the hint is visible.
- Press Add → the hint is not visible. Press Remove until no Remove button exists → the hint is visible again.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the empty-state hint must be shown when the list is empty (and not dismissed), and hidden when the list has items.`

### G01.2 — Never shown after dismissal in the session  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load: hint visible. Press the Dismiss button → hint not visible.
- Press Add (list non-empty, hint not visible), press Add again, then Remove until the list is empty → the hint is still not visible. Then Add once more → still not visible.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: after the user dismisses the hint it must never be shown again in the same session.`

### G01.3 — Returns in a new session  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load: Dismiss the hint (hint hidden). Start a new session (conventions). The list is empty and the hint is visible again.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the hint must return in a new session.`
