## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The four link columns are titled Product, Company, Resources and Legal, each with three text links. The newsletter signup has an email field labelled "Email" and a "Subscribe" button. There are at least two social icons, each an icon-only link (no visible text; inline vector icons, no image files). The copyright line is plain text. On phones the four columns may be stacked or turned into an accordion.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- link column = lowest ancestor that contains ≥ 2 links with visible text; the 4 groups with the most links are the columns
- accordion = ≥ 4 visible buttons with an `expanded` state; activating one makes more text links visible
- icon-only link = visible link with no visible text in itself or its descendants

## Checklist items

### L09.1 — 4 columns collapse to an accordion or stack on phones  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- At 1280 and 1024 px: 4 link columns found and their rects form one row.
- At 480 and 320 px: either (stack) 4 link columns found and their rects form one column; or (accordion) fewer than 4 columns visible, ≥ 4 visible buttons with `expanded` = false, and activating the first increases the number of visible text links.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the four link columns must sit in one row on wide screens and stack (or become an accordion) on phones.`

### L09.2 — Icons have names  `[A]`

**Operational definition**

- At 1280 px: ≥ 2 icon-only links (conventions); every one has a non-empty accessible name.
- Every icon in the page (visible svg/img, emoji-only text node) is decorative or named: hidden from the accessibility tree, or exposed as an `image` with a name, or inside a named link/button.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: every icon (including the social icons) must have an accessible name or be hidden from assistive technology.`

### L09.3 — Email field labelled  `[A]`

**Operational definition**

- At 1280 px: ≥ 1 visible text-input node (any text input role) exists, one of which has role `email-field` or a name matching /e-?mail/i. Every visible text input has a non-empty accessible name whose source is a label or an explicit name (`name_source` ∈ {label, aria}); a placeholder-only name does not count as a label.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the email field must have a label.`
