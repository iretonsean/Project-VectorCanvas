# L10 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Image-free feature grid: 6 features with icon, title and text in a 3×2 grid, 1 column on phones

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> Each of the six features has an icon (an inline vector icon or an emoji; no image files), a short title that is a heading, and one sentence of text. A section heading above the grid, if present, is a different heading level from the feature titles.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- feature titles = visible headings of level ≥ 2 at the one heading level that has exactly six of them
- cell = the largest ancestor of a title that contains no other feature title

## Checklist items

### L10.1 — Grid 3×2 → 1×6  `[A]`

**Operational definition**

- Six feature cells found. At 1280 and 1024 px the cells form rows [3,3] (3 columns, 2 rows). At 480 and 320 px the cells form one column of 6.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the six features must be a 3×2 grid on wide screens and a single column on phones.`

### L10.2 — Equal gaps  `[A]`

**Operational definition**

- At 1280 px: the 4 horizontal gaps between neighbouring cells in each row and the 3 vertical gaps between the two rows are all equal within 2 px. At 480 px the 5 vertical gaps between the stacked cells are equal within 2 px. (Gaps are measured between cell rects; shapes must be as in L10.1.)

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the gaps between the feature cells must all be equal.`

### L10.3 — Icons decorative or named  `[A]`

**Operational definition**

- At 1280 px: every one of the six cells contains ≥ 1 icon (visible svg/img node or emoji-only text node), and every icon is decorative or named (hidden from the accessibility tree, or an `image` with a name).

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: every feature must have an icon that is either decorative (hidden from assistive technology) or named.`
