# L08 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Event poster-style card: date block on the left, title, location with icon, "Add to calendar" link

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The date block shows a short month and a day number as separate lines (for example "OCT" and "12"). The card also has an event title (a heading), a location line with a small icon (an inline vector icon, no image files), and a link labelled "Add to calendar".

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- date tokens = visible text nodes that are a month abbreviation/name, a weekday abbreviation/name, or a 1–2 digit number (≤ 14 chars); the date block rect = union of those nodes
- title = the first heading, else the text node with the largest font size that is not a date token
- RTL is applied by the checker as direction:"rtl" (baseline: `dir="rtl"` on <html>; PVC: `direction:"rtl"` in the Snapshot request)

## Checklist items

### L08.1 — Date block left on LTR and right on RTL locales  `[A]`

**Operational definition**

- At 1280 px LTR: date block and title located; date block right edge ≤ title left edge + 2 px and they overlap vertically.
- At 1280 px with direction RTL: date block left edge ≥ title right edge − 2 px and they overlap vertically.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the date block must be on the left in left-to-right languages and on the right in right-to-left languages.`

### L08.2 — Icon decorative  `[A]`

**Operational definition**

- At 1280 px: the card (the nearest ancestor of the title that also contains the date block) contains ≥ 1 icon (visible svg/img node, or an emoji-only text node).
- Every icon is decorative or named: hidden from the accessibility tree (`a11y_hidden`), or an `image` with a non-empty name, or inside a named link/button. An emoji pictograph inside a text node that also contains other characters fails (it would be read out).
- Pass iff ≥ 1 icon exists and every icon is decorative-or-named.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the location icon must be present and decorative (hidden from assistive technology).`

### L08.3 — Link role is link  `[A]`

**Operational definition**

- At 1280 px: a visible node whose accessible name matches /add to calendar/i has role `link`.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: "Add to calendar" must be a link.`
