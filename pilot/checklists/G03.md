# G03 — checklist specification (stack-neutral)

**Category:** 4 Logic-heavy  |  **Primary baseline (G2):** B2  |  **Status:** written before any agent output exists.

**G2 intent:** Tabs with unsaved-changes guard: switching tabs with edits prompts "discard?"

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> Two tabs named "Profile" and "Notes" (tab semantics: a tab list with tabs and tab panels). Each tab has one multi-line text field. Typing in the text field of the current tab makes that tab "dirty". Switching to the other tab while the current tab is dirty asks "Discard changes?" with a "Discard" button and a "Cancel" button (either a browser confirm() dialog or an in-page dialog). Cancel stays on the current tab and keeps the typed text; Discard switches tabs and drops the text. Switching while the tab is not dirty switches immediately with no prompt.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- tabs = nodes with role `tab` (≥ 2); the selected tab has `states.selected` = true
- a prompt = a native confirm dialog (recorded by the browser driver; PVC has none) OR a visible `dialog`/`alert-dialog` node OR newly visible text matching /discard|unsaved|lose|changes/i
- cancel (in-page) = button named /^(cancel|keep|stay|no|go back|continue editing)/i; for a native confirm the driver dismisses it
- edit field = first visible `text-area` or `text-field`

## Checklist items

### G03.1 — Prompt only when dirty  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load. Activate the second tab (no edits yet) → no prompt, and the second tab becomes selected. Activate the first tab again (still clean) → no prompt.
- Then type "x" into the edit field of the first tab (dirty) and activate the second tab → a prompt is shown.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: switching tabs must prompt to discard only when the current tab has unsaved edits.`

### G03.2 — Cancel keeps the tab  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load; type "x" into the first tab's edit field; activate the second tab → prompt; cancel it (native: dismissed; in-page: press the Cancel button). Afterwards the first tab is still the selected tab and its edit field still contains "x".

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: cancelling the discard prompt must keep the current tab and its unsaved text.`
