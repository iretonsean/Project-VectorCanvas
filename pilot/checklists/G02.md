# G02 — checklist specification (stack-neutral)

**Category:** 4 Logic-heavy  |  **Primary baseline (G2):** B2  |  **Status:** written before any agent output exists.

**G2 intent:** To-do app: add, complete, delete, filter All/Active/Done, count of active items

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The app has a text field labelled "New task" and an "Add" button. Each task shows a checkbox, its text and a "Delete" button. Three filter buttons are named "All", "Active" and "Done". A line shows the number of tasks that are not done, written "N items left" (for example "3 items left", "1 item left").

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- new-task field = first visible text input (preferring a name matching /task|todo|new|add/i); add = button named /^add/i; filters = button/link/tab/radio named /^all/i, /^active/i, /^(done|completed)/i; per-task controls are found in the task's row (the largest ancestor of the task text that holds a checkbox/button and no other task text): checkbox = completes/uncompletes, a button named /delete|remove|×|✕|x/i = deletes
- count = first visible non-interactive text matching /(\d+) (items|tasks)? (left|remaining|active)/i; it always counts ALL tasks that are not done, regardless of the filter
- visible tasks = the set of known task texts that are visible; order is ignored

## Checklist items

### G02.1 — Counts correct after any sequence of 20 scripted operations (state trace)  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Apply the 20 scripted operations (SCRIPT in `core/specs/G02.mjs`: add, toggle (complete/uncomplete via the task checkbox), delete, filter) on a fresh load at 1280 px. After EACH operation compare against the reference model: (i) the set of visible task texts equals the model's tasks for the current filter (All = all, Active = not done, Done = done); (ii) the "items left" count equals the number of not-done tasks.
- Any operation whose control cannot be found, or any mismatch, fails the item; the detail names the step.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: after any sequence of add / complete / delete / filter operations the visible tasks and the count of active items must be correct.`
