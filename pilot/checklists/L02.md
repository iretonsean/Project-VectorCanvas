# L02 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Pricing page with three plans side by side; the middle one highlighted as "most popular"; stacks vertically on phones

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> Each plan shows a price (for example "$0", "$12", "$29"), a list of exactly four features, and one call-to-action button. Plans are Free, Pro and Team in that order; no external images or fonts are available.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- price = visible text node of ≤ 30 characters starting with a currency symbol + digit, a number + currency symbol, or the word "Free"
- plan container = for each price node, the lowest ancestor that contains at least one button/link; duplicates merged; page-level wrappers that contain another plan container are dropped
- features = nodes with role `list-item` inside the plan container

## Checklist items

### L02.1 — 3 columns ≥ 1024 px, 1 column ≤ 480 px  `[A]`

**Operational definition**

- Plan containers found as in the conventions; exactly 3 required.
- At 1024 and 1280 px: the 3 plan rects form one row (x-disjoint within 2 px, vertically overlapping ≥ 50%).
- At 480 and 320 px: the 3 plan rects form one column (y-disjoint within 2 px, horizontally overlapping ≥ 60% of the narrower).

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the three plans must be three columns at 1024 px and wider, and a single column at 480 px and narrower.`

### L02.2 — Middle plan visually distinct  `[H]`

**H item — not judged (D-5).** Reported as "not judged"; it does not enter the pass decision.

### L02.3 — Each plan has price, 4 features, CTA  `[A]`

**Operational definition**

- At 1280 px, for each of the 3 plan containers: ≥ 1 price node inside; exactly 4 visible `list-item` descendants; ≥ 1 visible `button` or `link` inside.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: each plan must have a price, exactly four features (as list items) and a call-to-action button.`
