# G05 — checklist specification (stack-neutral)

**Category:** 4 Logic-heavy  |  **Primary baseline (G2):** B2  |  **Status:** written before any agent output exists.

**G2 intent:** Wizard whose step 3 is skipped when the user answers "no" in step 2

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> A four-step wizard. Exactly one heading is visible at a time and it starts with "Step N" (N = 1 to 4), for example "Step 2: Pet". Every step has a "Next" button (on step 4 it may be named "Finish") and every step except the first has a "Back" button. Step 2 asks "Do you have a pet?" with two radio buttons named "Yes" and "No". Step 3 ("Step 3: Pet name") has a text field and is skipped when the answer to step 2 is "No". Step 4 is a summary. "Back" always returns to the step the user actually came from.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- current step = the number in the single visible heading whose text starts with /^step\s*\d+/i
- answer controls = radio (or button/checkbox/switch) named /^yes/i or /^no/i; next = button named /^(next|continue|finish)/i; back = button named /^(back|previous)/i

## Checklist items

### G05.1 — Skip logic correct both ways  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Fresh load at 1280 px starts on step 1. Next → step 2.
- Path "No": answer No, Next → step 4 (step 3 skipped). Path "Yes": (new fresh load) answer Yes, Next → step 3, Next → step 4.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: step 3 must be skipped when the answer in step 2 is "No" and shown when it is "Yes".`

### G05.2 — Back from step 4 returns to the right step  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- Path "No" to step 4, press Back → step 2. Fresh load, path "Yes" to step 4, press Back → step 3.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: Back from step 4 must return to the step the user came from (step 2 after "No", step 3 after "Yes").`
