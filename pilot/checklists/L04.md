# L04 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Holy-grail layout: header, left nav, main content, right sidebar, footer; sidebars collapse on tablets

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The left navigation has at least three links, the right sidebar has a short list of related links, and the main content is short (one heading and two or three sentences) so the page is shorter than the screen. No external resources are available.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- landmarks: header = role banner (or region named header/banner); left nav = navigation; main = main; right sidebar = complementary (or region named sidebar/aside/related/complementary); footer = contentinfo (or region named footer). [G4 §8.1 has no banner/contentinfo/complementary role: see PVC_CHECKER_NEEDS §6.1]
- a nav "toggle" = a visible button whose name matches /menu|nav|sidebar|toggle|hamburger|open|☰|≡/i, or any visible button with an `expanded` state

## Checklist items

### L04.1 — Five regions with landmark roles  `[A]`

**Operational definition**

- At 1280×800: each of header, nav, main, sidebar, footer found as a visible landmark (conventions).
- Arrangement: header bottom ≤ top of nav/main/sidebar (+2 px); footer top ≥ bottom of nav/main/sidebar (−2 px); nav right edge ≤ main left edge + 2; main right edge ≤ sidebar left edge + 2; nav, main, sidebar overlap vertically.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the page must have five regions with landmark roles (header, left navigation, main content, right sidebar, footer) arranged in the holy-grail layout.`

### L04.2 — Sidebars hidden ≤ 768 px with a way to reach the nav  `[A]`  *(scripted interaction; replayed by keyboard in U2)*

**Operational definition**

- At 768, 480 and 320 px, with main visible: the right sidebar is collapsed = not visible, or visible but not beside main (not in the same band side-by-side).
- The left nav is not shown as a side column beside main. Either it is visible and stacked (not beside main), or it is hidden (not visible) AND a visible nav toggle (conventions) exists such that activating it (pointer click / keyboard Enter) makes a visible `navigation` landmark with ≥ 2 visible links appear.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: at 768 px and narrower the sidebars must collapse, and the navigation must remain reachable.`

### L04.3 — Footer at the bottom of short pages  `[A]`

**Operational definition**

- Viewport 1280×1600 (taller than the content). footer = visible footer landmark. Pass iff footer bottom ≥ document height − 16 px (document height = max(content height, viewport height)), i.e. the footer sits at the bottom of the viewport on a short page.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: on a short page the footer must sit at the bottom of the screen.`
