# L03 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Landing hero: big headline, sub-headline, two buttons (primary and secondary), illustration on the right that moves below text on narrow screens

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> No image files or network resources are available: draw the illustration with inline vector shapes or styled boxes (at least 160 px wide on desktop). The hero has one headline, one sub-headline and exactly two buttons.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- illustration = the largest visible leaf block that has an image/graphic or a solid fill and contains no text or controls
- hero text column = every other visible text node and button/link

## Checklist items

### L03.1 — Reflow at the breakpoint  `[A]`

**Operational definition**

- Illustration and text column as in the conventions.
- At 1280 and 1024 px: the illustration lies to the RIGHT of the text column (illustration.x ≥ the largest right edge among text/button nodes − 2 px) and overlaps the text column vertically.
- At 480 and 320 px: the illustration lies BELOW the text column (illustration.y ≥ the largest bottom edge among text/button nodes − 2 px) and overlaps it horizontally.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the illustration must sit on the right of the text on wide screens and move below the text on narrow screens.`

### L03.2 — Primary vs secondary styling distinct  `[H]`

**H item — not judged (D-5).** Reported as "not judged"; it does not enter the pass decision.

### L03.3 — Headline is a level-1 heading  `[A]`

**Operational definition**

- At 1280 px: exactly one visible node has role `heading` with `states.level` = 1, and its text is the node with the largest font size among all visible text nodes (ties allowed).

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the headline must be the page's single level-1 heading.`
