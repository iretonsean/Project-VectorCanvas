# L05 — checklist specification (stack-neutral)

**Category:** 1 Layout-heavy  |  **Primary baseline (G2):** B1  |  **Status:** written before any agent output exists.

**G2 intent:** Photo-free blog article page: title, author line, 6 paragraphs, a pull quote, comfortable reading width

Source of truth for the checklist items: `docs/G2_Benchmark_Corpus.md` §5 (main @ 5fdd412). Item order and wording below follow the G2 row. **A** = automatable (decided by the checker from observables), **H** = human-judged: *not judged (D-5)*; pass is decided on A items only.

## Fixture

Sentence(s) to append **verbatim** to the intent text, for **both** stacks (needed so the A items can be evaluated; the G2 intent alone does not contain this data):

> The article has one title (the page's top-level heading), an author line, six body paragraphs of two to four sentences each, and one pull quote that is not one of the six paragraphs. Section headings, if any, are exactly one level below the title.

## How the checks observe the app

All checks are predicates over the stack-neutral **Snapshot** (`PVC_CHECKER_NEEDS.md` §1) and a small event vocabulary (click, type, key, new session). Baseline: Chromium 141, offline, DOM geometry + Chromium accessibility tree. PVC: `pvc_runtime` headless. Geometry widths: 320, 480, 768, 1024, 1280 px; default height 800; text scale 1 unless stated.

**Locator conventions used by this specimen:**

- body text = visible nodes with ≥ 2 laid-out lines at 1280 px and the most common font size among such nodes (a pull quote set in a different size is therefore excluded automatically)

## Checklist items

### L05.1 — Line length 45–90 characters at desktop  `[A]`

**Operational definition**

- At 1280×800. Body blocks = visible nodes with ≥ 2 lines (`line_chars`) whose font size equals the most common font size among multi-line text nodes; at least 3 such blocks are required.
- Take every line except the last of each block (full lines). Pass iff the median of these line lengths is within [45, 90] AND at least 90% of them lie within [40, 95] (±5 characters of tolerance for ragged-right wrapping).

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: body text lines must be 45–90 characters long at desktop width.`

### L05.2 — Pull quote visually distinct  `[H]`

**H item — not judged (D-5).** Reported as "not judged"; it does not enter the pass decision.

### L05.3 — Heading hierarchy correct  `[A]`

**Operational definition**

- Headings = visible nodes with role `heading`, in reading order, at 1280 px. Pass iff: ≥ 1 heading; the first heading has level 1; exactly one level-1 heading; and no heading's level exceeds the previous heading's level by more than 1.

**Standardised failure text (the only repair feedback for this item, G2 §4.4):** `Not met: the heading hierarchy must be correct (one top-level title first, no skipped levels).`
