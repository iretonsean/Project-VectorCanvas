# RFC note: `icu_normalizer =2.3.0` (pvc-ir)

**What:** ICU4X Unicode normalisation (NFC/NFD/NFKC/NFKD) with compiled data. **Version:** exactly `=2.3.0` (+ `icu_normalizer_data 2.3.0`, `icu_collections`, `icu_provider 2.3.1`, `icu_locale_core`, `zerovec`, `smallvec`, `utf16_iter`…). **Not on the D-10 list; approved by the Supervisor on 2026-10-08 (message to dev-ir).**
**Why nothing pinned covers it:** G4 §3 requires strings in canonical form to be Unicode NFC, which needs a normalisation table. Nothing in the G7 table exposes one directly, and PVC must not hand-write Unicode tables. `icu_normalizer 2.3.0` is already in the pinned graph's Cargo.lock (feasibility `pinprobe.Cargo.lock`) and ICU4X is the G6-sanctioned stack (G6 §1), so it adds no new family of code to the final binary. Used only via `ComposingNormalizerBorrowed::new_nfc()` in `pred::nfc`.
**What it pulls in:** the ICU4X support crates above plus the build-time proc-macro `displaydoc`/`synstructure`/`yoke-derive`/`zerofrom-derive` chain. Default features (`compiled_data`). `no_std`-capable; builds for `wasm32-unknown-unknown` (checked, `evidence/d1-wasm.txt`).
**Hard-wall check:** `cargo tree -e normal` (both targets) has no HTTP/socket/LLM/async-runtime crate (`evidence/hardwall-scan.txt`); the data is compiled in, nothing is fetched at run time. **Fallback if it must be dropped:** `unicode-normalization 0.1.x` (needs a fresh RFC).
